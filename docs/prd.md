## 1. 产品愿景

AI 作业批改工具帮助家长高效检查小学阶段孩子的试卷和作业。用户用手机拍照上传试卷，AI 直接在原图上标注批改结果——正确处打勾、错误处打问号、错题旁附解题思路——返回一张可直接查看的批改后图片。试卷和批改结果自动存入后端，系统对错题进行归类统计，支持一键生成错题集试卷，供孩子针对性复习。

MVP 覆盖**英语**和**数学**两门学科，支持印刷体试卷与手写作答混合识别的真实场景。后续扩展语文作文、报听写等多学科功能。

## 2. 目标用户画像

**主要用户：小学生家长**

- 孩子就读小学（当前场景：五年级 + 二年级）
- 每天需要检查试卷、练习册、听写本的作业批改
- 痛点：检查耗时长（每天30-60分钟），且家长对英语/数学的批改准确率不稳定，尤其是英语作文和阅读理解
- 现有方案：纯手工核对答案，无系统化记录
- 关心：批改速度、准确率、错题整理、操作简单（拍照即得结果）
- 不关心：复杂的数据报表、社交分享、积分排行

**次要用户：学生自查**

- 做完试卷后先拍照自检，发现明显错误后再给家长终审
- 关心：即时反馈、解题思路提示

**规模路径：** MVP 阶段家庭内部试用 → 小范围亲友试用 → 对外开放

## 3. 功能需求

### F-01: 试卷拍照上传 [MUST]

用户用手机拍照或从相册选择试卷图片，上传至后端批改。→ 架构 §6.1, UX §2.1, OpenAPI `POST /api/submissions`

- **AC-01:** 支持 `<input capture="environment">` 直接调起后置摄像头拍照
- **AC-02:** 支持从相册选取已有图片
- **AC-03:** 上传前在浏览器端自动压缩：最长边 ≤ 2048px，JPEG 质量 80%
- **AC-04:** 上传时显示进度指示
- **AC-05:** 提交表单包含：图片、学科（英语/数学）、当前家长手机号、小朋友（从家长管理列表中选取）
- **AC-06:** 支持格式：JPEG、PNG；iOS 设备生成的 HEIC 格式由前端自动转为 JPEG 后上传
- **AC-07:** 上传时自动关联当前家长，数据按手机号隔离
- **AC-08:** 上传后前端进入轮询状态（每 2 秒查询结果），直到批改完成或失败

### F-02: AI 批改引擎 [MUST]

后端接收图片后，调用 GLM-4V 多模态大模型执行识别和批改。

- **AC-01:** 输入：试卷图片 + 学科类型
- **AC-02:** GLM-4V 输出结构化批改数据：逐题题号（支持复合编号）、位置坐标（百分比）、判定结果（对/错）、错题解题思路、错误类型分类
- **AC-03:** 批改流程为异步：上传后立即返回 202 + submission_id，后台调用 GLM-4V 并标注图片，前端轮询结果
- **AC-04:** 覆盖数学全部题型：计算题、应用题
- **AC-05:** 同时处理打印体（题目）和手写体（作答），不做区分对待
- **AC-06:** 解题思路仅针对错题生成，正确题不输出
- **AC-07:** 记录每次 API 调用的 token 消耗，用于月度预算监控
- **AC-08:** 模型选择（Flash / Plus）由后端环境变量控制，前端不可见也不可选择
- **AC-09:** 数学试卷中的几何图形、算式竖式等内容，若 GLM-4V 识别效果不理想，预留接入专项数学 OCR 作为补充方案

### F-03: 批改结果标注与返回 [MUST]

将 AI 返回的批改结果标注到原图上，返回一张批改后图片。

- **AC-01:** 基于 GLM-4V 返回的坐标数据，在原题对应位置标注：正确题绿色勾（✓），错误题红色问号（？）
- **AC-02:** 标注不遮挡原题内容，文字清晰可读
- **AC-03:** 错题旁叠加解题思路文字，使用项目打包的中文字体确保跨平台一致
- **AC-04:** 根据坐标数据从原图裁剪每道题的独立图片，供错题集和试卷生成使用
- **AC-05:** 返回完整 URL 可访问的批改后图片
- **AC-06:** 同时返回结构化批改详情（逐题数据，供前端渲染明细视图）
- **AC-07:** 支持人工修正：用户可在批改结果中手动更改某道题的判定（对/错），修正后同步更新错题集

### F-04: 家长与小朋友管理 [MUST]

家长通过手机号标识身份，一个家长下可管理多个小朋友。手机号后续作为登录凭据。

- **AC-01:** 首次使用时家长输入手机号，系统以此作为唯一标识（当前信任输入，不验证）
- **AC-02:** 支持新增小朋友（名字必填），关联到当前家长
- **AC-03:** 支持编辑、删除小朋友名字；删除名字不删除对应的历史试卷数据
- **AC-04:** 首次使用时预置默认小朋友列表（如"小朋友1"、"小朋友2"），家长可自由修改
- **AC-05:** 同一手机号在不同设备上看到相同的小朋友列表（数据按手机号隔离）
- **AC-06:** 一个小朋友只属于一个家长（单一归属），未来支持多家长关联需引入授权机制

### F-05: 历史提交浏览 [MUST]

用户可以回溯查看过往的批改记录。

- **AC-01:** 按当前家长手机号限定数据范围，按小朋友名字进一步筛选
- **AC-02:** 每条记录卡片展示：缩略图、学科、得分（正确数/总题数）、提交时间
- **AC-03:** 点击卡片进入详情：原图 + 批改后图片对照，逐题明细列表
- **AC-04:** 列表支持分页（默认每页 20 条）

### F-06: 错题集管理 [MUST]

系统自动将每次提交中的错题归入错题集，支持多维度筛选。

- **AC-01:** 自动归集：每次批改完成后，错题自动计入对应小朋友的错题集。同一张试卷内同一题号的错误合并为一条；跨试卷不做去重（不同试卷的同题号内容不同，需 v2 相似度匹配）
- **AC-02:** 筛选维度：按时间范围（开始日期-结束日期）
- **AC-03:** 筛选维度：按题型（英语：选择题/填空题/阅读理解/作文；数学：计算题/应用题）
- **AC-04:** 筛选维度：按学科（英语/数学）
- **AC-05:** 错题列表展示：题目截图、试卷来源、出错时间

### F-07: 错题试卷生成 [SHOULD]

根据错题集筛选结果，生成一份可打印的错题练习试卷。

- **AC-01:** 生成参数：小朋友名字、学科、题型（可多选）、时间范围、题目数量（1-50，默认10）
- **AC-02:** 输出一张合成图片：包含所选错题题目区域的排版集合
- **AC-03:** 试卷顶部有标题栏（小朋友名字 + 学科 + 日期）
- **AC-04:** 每道错题下方留作答空白区域

### F-08: 跨设备访问（同手机号多设备一致）[MUST]

一个家长手机号可挂载并查看自己名下的多个小孩；同一手机号在多个设备上看到一致的数据。

- **AC-01:** 同一手机号在不同设备上看到相同的小朋友列表和历史数据
- **AC-02:** 数据按手机号隔离，不同手机号之间互不可见
- **AC-03:** MVP 不支持多家长共享同一小孩（需授权机制，属未来能力）

## 4. 约束（不可协商）

- **C-01 交付时间**：MVP 须在一周内交付可试用版本（单人 + AI 辅助开发）。
- **C-02 API 预算**：GLM-4V 月度费用 ≤ 50 元；优先免费模型 `GLM-4V-Flash`。
- **C-03 部署形态**：MVP 本地部署，IP+端口访问，无域名/HTTPS；后续上阿里云。
- **C-04 存储依赖**：图片存本地文件系统，不依赖云存储；数据库为 MySQL。
- **C-05 身份模型**：手机号作为家长唯一标识，无注册/登录/密码；数据按手机号隔离。
- **C-06 多人范围**：MVP 仅支持一个家长手机号查看自己挂载的多个小孩；不支持多家长共享同一小孩。
- **C-07 平台**：Web 移动端优先（375px 基准）；不做小程序/App。

## 5. 非功能需求

- **N-01: 性能** — 拍照到返回批改结果的目标等待时间 5-15 秒（含 GLM-4V API 调用），硬上限 30 秒（超时即置 failed）。页面首屏加载 < 2 秒（3G）。
- **N-02: 移动端适配** — 所有页面以 375px 宽度为设计基准，触控目标 ≥ 44×44px。支持 iOS Safari 和 Android Chrome 最新两个大版本。
- **N-03: 图片质量** — 前端压缩后图片文字仍清晰可辨。批改标注不遮盖原题文字。
- **N-04: 成本控制** — GLM-4V API 月度费用 ≤ 50 元。MVP 优先使用免费模型 `GLM-4V-Flash`。每次调用后记录 token 消耗。
- **N-05: 数据安全** — MVP 阶段为家庭自用，图片存本地文件系统。数据库密码、API Key 通过环境变量注入，不硬编码。
- **N-06: 可用性** — 后端 99% 可用（本地部署，随开随用）。无外部云服务依赖（除 GLM-4V API）。

## 6. 内容策略与约束

- 用户生成内容为试卷图片和小朋友名字。MVP 阶段仅家庭自用，不设内容审核。
- 小朋友名字仅作为区分标识，不收集年龄、学校、联系方式等个人信息。
- 无用户注册/登录，无密码。数据隔离依赖手机号区分（信任模型：家庭内部使用）。
- 试卷图片不执行脱敏处理（MVP 自用阶段；对外开放前必须加入）。

## 7. 明确不做（MVP）

- 用户注册/登录系统
- 图片脱敏处理
- 微信小程序 / 移动原生 App
- 云端图片存储（本地文件系统）
- 家长端 vs 学生端角色区分
- 通知/提醒/推送
- 批改结果导出 PDF
- 语文作文、报听写等学科（仅做英语 + 数学）
- 学习趋势分析、分数曲线图等数据报表
- 对外 API 或第三方集成
- 多家长共享同一小孩（需授权机制，属未来能力）

## 8. 已决议事项

- **OQ-01（错题去重）:** 合并为一条记录，记录错误次数和每次出错的时间列表。
- **OQ-02（人工修正）:** 需要。用户可在批改结果中手动更改某道题的判定，修正后同步更新错题集。
- **OQ-03（名字管理）:** 系统预设默认名字列表（如"小朋友1"、"小朋友2"），家长可自由编辑（增/删/改）。见 F-04。
- **OQ-04（模型切换）:** GLM-4V 模型选择（Flash / Plus）由后端环境变量控制，前端不可见。免费版不可用时运维层面直接切换，无需用户确认。
- **OQ-05（数学 OCR 补充）:** 需要。若 GLM-4V 对几何图形、算式竖式等识别效果不理想，后续将引入专项数学 OCR 作为补充。见 F-02 AC-09。

## 9. 词汇表

| 术语 | 含义 |
|------|------|
| **Parent / 家长** | 通过手机号标识的用户身份。一个 phone 对应一个家长记录。 |
| **phone** | 家长手机号，MVP 阶段作为唯一身份标识（不验证真伪）。 |
| **Child / 小朋友** | 隶属于某个家长的学生档案。一个家长可挂载多个小孩。 |
| **Submission / 提交** | 一次试卷拍照上传及批改的完整记录。 |
| **GradedQuestion / 批改明细** | 单次提交中某道题的判定结果（对/错、题型、坐标、解题思路）。 |
| **ErrorQuestion / 错题** | 错题集条目。MVP 阶段同次提交内按题号去重，跨试卷不去重。 |
| **question_position** | 题目在图片上的位置，百分比坐标（0-100），由 GLM-4V 返回。 |
| **标注（annotation）** | 在原图上叠加 ✓/？/解题思路，生成批改后图片。 |
| **人工修正** | 家长手动覆盖某题的 AI 判定，同步更新错题集。 |
