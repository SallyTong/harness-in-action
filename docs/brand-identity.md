## Section 1: 为什么 AI 代码看起来千篇一律

先明确**不要什么**，再说要什么：

### 1.1 Tailwind 默认症
- `rounded-lg` 到处用，所有组件圆角一模一样
- `bg-gray-50` / `bg-gray-100` 只有两三种灰色
- `p-4 gap-4` 到处都是 16px 间距
- `shadow-sm` 作为唯一阴影层级
- `text-gray-500` 作为唯一的二级文字色

### 1.2 排版扁平化
- 全用系统字体，标题和正文没有区别
- 只有"普通"和"大一点"两种字号
- 没有字重变化，没有行高差异

### 1.3 布局单调
- 所有内容居中排列在等宽卡片中
- 移动端只是桌面端挤成单列

### 1.4 缺少个性
- 按钮文案："提交"、"取消"、"保存"、"删除"
- 空状态："暂无数据" + 灰色图标
- 加载：居中 spinner，没有别的

### 1.5 暗黑模式崩塌
- MVP 只做浅色模式（日间使用场景），不做暗黑模式

## Section 2: 品牌方向

### 2.1 品牌核心

**温暖、可靠的家庭教育工具**——让家长省心，让孩子进步的 AI 批改助手。

### 2.2 品牌属性

| 维度     | 本项目 IS                               | 本项目 IS NOT                     |
| -------- | --------------------------------------- | --------------------------------- |
| 情绪     | 温暖、安心、清晰                        | 娱乐化、幼稚、冷冰冰               |
| 密度     | 透气、聚焦、一次一件事                  | 拥挤（像 dashboard）或过于稀疏     |
| 色彩     | 暖白底色 + 温和的蓝靛主色 + 绿色肯定感   | 荧光色、暗黑、灰色主导              |
| 字体     | 干净清晰、可读性高、层级分明             | 花哨装饰、手写体、等宽字体          |
| 交互     | 快速响应、有反馈、鼓励性                 | 跳转频繁、生硬切换、弹窗轰炸        |

### 2.3 目标用户审美

家长群体（30-45 岁），日常使用微信、淘宝、支付宝。习惯简洁高效的工具类产品——不追求炫酷，追求"好用、看得清、不出错"。对 AI 批改的信任感来自结果的清晰展示，而非技术感的设计。

### 2.4 竞品视觉定位

| 竞品/参照 | 它们的样子                             | 我们的差异                                   |
| --------- | -------------------------------------- | -------------------------------------------- |
| 一起作业   | 师生互动、卡通化、功能入口多            | 更聚焦家长视角，一次只做"批改"一件事         |
| 小猿搜题   | 学生自主、拍照搜题为主                  | 强调批改而非搜答案，家长掌控感               |
| 微信小程序 | 极简白 + 品牌绿，单列布局               | 参考其简洁布局，但用更温暖的色彩和更少的入口 |

**设计参照：** Apple"健康"App（清晰的数据卡片 + 单一焦点）、微信（极简 chrome、单列）、支付宝蚂蚁森林（温暖的绿色 + 正向反馈）。

## Section 3: 色彩系统

### 3.1 核心色板

```css
:root {
    /* 背景层级（最浅到最深） */
    --color-bg-page: #F8F6F4;       /* 页面底色：暖白 */
    --color-bg-card: #FFFFFF;       /* 卡片/面板底色：纯白 */
    --color-bg-hover: #F3F0ED;      /* 悬停态 */
    --color-bg-overlay: #FFFFFF;    /* 弹出层 */

    /* 文字层级 */
    --color-text-primary: #1E1B18;   /* 标题、重要内容 */
    --color-text-secondary: #6B6560; /* 描述、元信息 */
    --color-text-tertiary: #A39D97;  /* 占位符、禁用 */

    /* 主色 — 温和蓝靛（信任感 + 教育感） */
    --color-accent: #6366F1;         /* 主按钮、链接、聚焦环 */
    --color-accent-hover: #4F46E5;   /* 悬停 */
    --color-accent-subtle: #EEF2FF;  /* 主色浅底（标签、选中态） */

    /* 语义色 */
    --color-success: #22C55E;        /* 正确 ✓，绿色勾 */
    --color-success-bg: #F0FDF4;     /* 正确背景 */
    --color-error: #EF4444;          /* 错误 ✗，红色问号 */
    --color-error-bg: #FEF2F2;       /* 错误背景 */
    --color-warning: #F59E0B;        /* 警告 */
    --color-warning-bg: #FFFBEB;     /* 警告背景 */

    /* 边框 */
    --color-border: #E5E0DA;         /* 卡片/输入框边框 */
    --color-border-light: #F0EDE8;   /* 分割线 */
}
```

### 3.2 通过验证的色彩配对

| 前景                    | 背景                | 对比度  | 用途            | WCAG AA |
| ----------------------- | ------------------- | :-----: | --------------- | :-----: |
| `--text-primary`        | `--bg-page`         | 17.1:1  | 正文            | ✅      |
| `--text-primary`        | `--bg-card`         | 17.6:1  | 卡片内文字       | ✅      |
| `--text-secondary`      | `--bg-page`         | 5.8:1   | 元信息           | ✅      |
| `--text-secondary`      | `--bg-card`         | 6.0:1   | 卡片内元信息     | ✅      |
| `--text-tertiary`       | `--bg-card`         | 3.1:1   | 占位符（装饰性） | 豁免   |
| `#FFFFFF`               | `--color-accent`    | 4.9:1   | 主按钮文字       | ✅      |
| `--color-success`       | `--bg-card`         | 3.3:1   | 图标装饰         | 豁免   |
| `--color-error`         | `--bg-card`         | 3.5:1   | 图标装饰         | 豁免   |

> 正确/错误图标同时带有数字和颜色，不以颜色为唯一信息传达方式。

### 3.3 禁用色

代码中禁止出现以下 Tailwind 灰色默认值：
`bg-gray-*`、`bg-zinc-*`、`bg-slate-*`、`bg-neutral-*`、
`text-gray-*`、`text-zinc-*`、`text-slate-*`、`text-neutral-*`

使用上述自定义色板或 Tailwind 的 `indigo-*`、`red-*`、`green-*`、`amber-*` 系列。

## Section 4: 字体

### 字体选择

| 角色   | 字体                            | 字重    | 用途                   |
| ------ | ------------------------------- | ------- | ---------------------- |
| 正文   | -apple-system, "PingFang SC"    | 400, 500| 所有中文正文、标签      |
| 数字   | "SF Mono", "Menlo", monospace   | 500     | 得分、统计数据          |

> 中文字体使用系统自带苹方（iOS/macOS）和微软雅黑（Windows），无需加载 Web Font。英文和数字回退到系统 SF / Segoe UI。
>
> **注意区分两种字体用途：**
> - **UI 字体**（本节）：页面文字、按钮、标签，用系统字体，不打包。
> - **图片标注字体**（批改后图片上的解题思路文字）：用项目打包的思源黑体（Noto Sans SC），见架构 AD-11。两者不同，勿混淆。

### 字号层级

| Token          | 大小  | 行高  | 字重 | 用途                     |
| -------------- | :---: | :---: | :--: | ------------------------ |
| `--text-3xl`   | 28px  | 36px  | 600  | 得分大数字（"8/10"）     |
| `--text-2xl`   | 22px  | 30px  | 600  | 页面标题                 |
| `--text-xl`    | 18px  | 26px  | 500  | 区块标题、卡片标题        |
| `--text-base`  | 15px  | 22px  | 400  | 正文、描述               |
| `--text-sm`    | 13px  | 18px  | 400  | 元信息、时间戳            |
| `--text-xs`    | 11px  | 14px  | 500  | 标签、题型 badge          |

**规则：** 每个页面至少使用 3 种不同字号。

## Section 5: 间距与布局

### 间距尺度

```css
--space-1: 4px;   --space-2: 8px;   --space-3: 12px;
--space-4: 16px;  --space-5: 20px;  --space-6: 24px;
--space-8: 32px;  --space-10: 40px; --space-12: 48px;
```

**规则：** 每个页面至少使用 3 种不同间距值。`p-4 gap-4` 通篇一样算违规。

### 布局原则

- **移动端 375px 基准**：内容区左右留 `--space-4`（16px）边距
- **桌面端**：最大内容宽度 480px 居中，底部导航保持在底部
- **卡片内**：标题与正文间距 `--space-1`（4px），卡片之间 `--space-3`（12px）
- **章节之间**：用 `--space-8`（32px）分隔，制造呼吸感
- **拍照上传区**：虚线边框大矩形，内部留白充足，引导视觉聚焦

## Section 6: 视觉语言

### 6.1 圆角策略

| 组件         | 圆角      | 理由                           |
| ------------ | :-------: | ------------------------------ |
| 主按钮       | 12px      | 温暖友好，不是冷冰冰的工具        |
| 卡片         | 14px      | 内容容器稍大圆角，给人安全感      |
| 输入框       | 10px      | 略显圆润，与按钮协调              |
| 拍照上传区   | 16px      | 大圆角，友好的引导感              |
| 标签/Badge   | 9999px    | 胶囊形，小而精致                  |
| Toast 提示   | 10px      | 紧凑                          |

**规则：** 不同组件类型使用不同圆角。全部 `rounded-lg` 算违规。

### 6.2 阴影与层级

浅色模式下使用轻微阴影区分层级：

| 层级   | 处理                                   | 用途              |
| :----: | -------------------------------------- | ----------------- |
| 0      | 无阴影，融入 `--bg-page`                | 页面背景           |
| 1      | `shadow-sm`（轻微投影）                 | 卡片、列表项       |
| 2      | `shadow-md` + 半透明背板                | 底部 ActionSheet  |
| 3      | `shadow-lg` + 半透明背板                | 全屏图片预览       |

### 6.3 边框

| 场景          | 边框                         |
| ------------- | ---------------------------- |
| 卡片/输入框    | `border` `--color-border`    |
| 分割线        | `border-b` `--color-border-light` |
| 聚焦态        | `ring-2 ring-indigo-400`     |
| 拍照上传区     | `border-2 border-dashed` `--color-border` |
| 错题行强调     | `border-l-2 border-red-400`  |

### 6.4 渐变

无装饰性渐变。仅在滚动列表底部使用淡出遮罩（`linear-gradient` 到 `--bg-page`）。

## Section 7: 图标系统

### 图标库

**Lucide Icons**（lucide.dev）——简洁笔画风格，24px 网格，与 React 生态集成好。

不用 Heroicons（太"Tailwind 模板感"），不用 Emoji 作为功能图标（风格不统一）。

### 图标尺寸

| 场景         | 大小  | 备注                 |
| ------------ | :---: | -------------------- |
| 底部导航     | 22px  | 选中态用主色填充变体  |
| 行内操作     | 16px  | 编辑、删除等小图标    |
| 空状态       | 48px  | `--text-tertiary` 色 |
| 状态指示     | 14px  | ✓ / ？               |

### 风格规则

- 描边宽度：1.5px（Lucide 默认）
- 颜色：图标继承文字色。仅当前激活的导航图标使用主色
- 状态图标（✓/？）不使用 Lucide，使用自定义 SVG 以保证与批改图片标注一致

## Section 8: 图片与插图

### 8.1 核心图片：试卷

这是本产品最核心的视觉元素。批改后的试卷图片需：

- 全宽展示，可双指缩放
- 批注颜色与 UI 语义色一致：绿色勾（`#22C55E`）、红色问号（`#EF4444`）
- 解题思路文字使用黑色/深灰，与试卷印刷文字协调

### 8.2 空状态

| 场景           | 图标（Lucide）      | 标题                       | 操作按钮     |
| -------------- | ------------------- | -------------------------- | ------------ |
| 无历史记录     | `clipboard-list`    | "还没有批改记录"            | "去批改"     |
| 无错题（全局）  | `sparkles`          | "🎉 还没有错题，继续保持！"  | "去批改"     |
| 无错题（筛选后）| `filter`            | "没有符合条件的错题"         | "清除筛选"   |
| 无小朋友       | `user-plus`         | "请先添加小朋友"            | "添加"       |

**布局：** 图标居中置顶（48px, `--text-tertiary`），标题在图标下方 `--space-3`，操作按钮在标题下方 `--space-4`。

### 8.3 不使用
- 无插画（illustration）
- 无装饰性 hero 图片
- 无 AI 生成的装饰图

## Section 9: 动效

### 9.1 过渡规则

- **时长：** 快 100ms（hover）、中 200ms（面板/下拉）、慢 300ms（页面切换）。不超过 400ms
- **缓动：** 入场 `ease-out`，退场 `ease-in`，变形 `ease-in-out`
- **动画内容：** 透明度、滑入（ActionSheet）、缩放（全屏图片）、高度变化（折叠展开）
- **不动画：** 文字颜色变化、布局重排、滚动位置
- **减少动画：** 尊重 `prefers-reduced-motion`，替换为即时状态切换

### 9.2 加载状态

| 场景               | 处理                                                   |
| ------------------ | ------------------------------------------------------ |
| 页面首次加载       | 骨架屏（Skeleton），匹配内容布局，脉冲动画 1.5s 周期      |
| 操作进行中（提交）  | 按钮内 spinner（16px）替换图标，按钮禁用                  |
| 列表加载更多       | 底部"加载更多…" + spinner                               |
| 批改中             | 大号 ✏️ 旋转动画 + 文案轮播 + 不确定进度条                |
| 轮询等待           | 脉动指示器 + "AI 正在批改…"（每 2 秒切换文案）           |

## Section 10: 文案语调

本产品面向家长，文案应：

- **简洁直接：** "批改完成" 而非 "您的试卷已经成功完成批改"
- **鼓励性但不幼稚：** "🎉 全对！太棒了！" 适合小朋友场景；家长看到的是 "8/10，继续加油"
- **具体：** "请选择小朋友" 而非 "请填写必要信息"
- **不用 AI 术语：** UI 中不出现"模型"、"prompt"、"AI 生成"等词汇。用"批改"替代"AI 批改"
- **不用职场套话：** 避免"赋能"、"解决方案"、"智能"

按钮文案示例：

- "开始批改"（不是"提交"）
- "重新批改"（不是"重试"）
- "保存修改"（不是"更新"）
- "移除"（不是"删除"）

## Section 11: 反通用化检查清单

每个页面/组件开发完成后逐项核对。**最低通过分：27/32。**

### 字体（7 项）
1. [ ] 本页面至少使用 3 种不同字号
2. [ ] 至少 2 种字重可见
3. [ ] 标题和正文有明显层次区别
4. [ ] 标题和正文字高不同
5. [ ] 无 `text-gray-*` 默认色
6. [ ] 数字/得分使用等宽字体
7. [ ] 中文字体优先使用系统苹方/微软雅黑

### 色彩（6 项）
8. [ ] 无禁用 Tailwind 灰色
9. [ ] 主色（indigo）仅在 1-2 个焦点出现，不滥用
10. [ ] 正文对比度 ≥ 4.5:1
11. [ ] 卡片底色与页面底色有明显区分
12. [ ] 交互元素有 hover / focus / active 三态
13. [ ] 所有文字/背景配对在许可表中

### 布局（5 项）
14. [ ] 本页面至少使用 3 种不同间距值
15. [ ] 相关内容紧凑，不同区块有明显分隔
16. [ ] 布局不是居中等宽卡片列
17. [ ] 桌面端（≥768px）最大宽度 480px 居中
18. [ ] 有明显留白区域

### 视觉语言（4 项）
19. [ ] 圆角按组件类型区分（按钮≠卡片≠标签）
20. [ ] 阴影层级遵循定义
21. [ ] 聚焦环使用 `ring-2 ring-indigo-400`
22. [ ] 图标来自 Lucide，尺寸匹配规范

### 交互（4 项）
23. [ ] 按钮文案具体到操作
24. [ ] 至少一个微交互（hover 颜色变化、按下缩放等）
25. [ ] 加载状态匹配定义（骨架屏而非全页 spinner）
26. [ ] 空状态有视觉处理 + 下一步操作

### 文案（3 项）
27. [ ] UI 中无"模型"、"prompt"、"AI"等术语
28. [ ] 错误信息具体可操作
29. [ ] 占位文字真实有帮助

### 视觉验证（3 项）
30. [ ] 本页面与同类竞品（小猿搜题、一起作业）有视觉区分
31. [ ] 即使隐藏 Logo 也能看出品牌特色
32. [ ] 375px 和 768px 下无裁剪/溢出
